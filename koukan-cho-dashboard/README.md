# 官公庁 入札・落札データ分析 × DI受注戦略ダッシュボード

Data-Walkers「政府調達・入札落札データ」API の実データをもとに、官公庁調達案件を
**業界業種 / 案件概要 / DIとの親和性 / もし入札していた場合の落札可能性** の4観点で
スコアリングし、デジタルアイデンティティ(DI)の受注戦略に落とし込む分析ダッシュボード。

> 元記事: 官公庁の入札・落札データで上場企業の受注動向を調べる (Qiita / @alt_data)

## 入札戦略シミュレータ (strategy.html)

参加を検討する案件を選び、「現状のままの勝率」→「エージェント戦略立案後の勝率」→
「RFP読込・マーケ戦略後の勝率」を段階的に試算する新ページ。各案件の🎯リンクからも遷移できる。

| ステップ | 内容 |
|---|---|
| ① 案件検索・抽出 | **2ソース切替**: (a)過去の落札実績43,008件、(b)**いま公示中の案件**(官公需ポータル・入札期日つき)。行クリックで選択(`?id=`深リンク対応) |
| ② 現状勝率(As-Is) | 親和性×現職係数×金額障壁 ÷ 推定入札者数 ×2 の内訳つき。競合・コンペを織り込み挑戦者の上限は60% |
| ③ エージェント戦略会議 | 5エージェント=案件分析🧭/競合分析⚔️/価格戦略💴/提案・マーケ📣/体制・実績🏗️ が分析と勝率寄与係数を提示 |
| ④ 戦略後勝率(To-Be) | 係数を乗算適用したウォーターフォール(戦略後の上限65%、As-Isを下回らない) |
| ⑤ RFP・企画書読み込み | **ドラッグ&ドロップ(PDF/txt/md/csv)またはファイル選択・貼り付け**に対応。約40種のキーワードで解析し適合で最大+12%相対、領域外検出で警告と減点 |
| ⑥ 価格戦略の詳細 | 推定予定価格(落札率88%仮定)・推奨入札レンジ(企画競争90-95%/価格競争82-88%)・対大手SIのコスト優位 |
| ⑦ 総合判定 | 入札推奨/条件付き/見送りの判定と実行アクション |

エージェントはルールベースの戦略シミュレーション(LLM不使用・静的サイトで完結)。勝率はすべて推定値。

### 公示中案件の取得 (api/open-bids.js)

Data-Walkersのデータは**落札済み(過去実績)**のみのため、「いま公示中(入札受付中)」の案件は
**官公需情報ポータル(kkj.go.jp)の公開API**から取得する。CORS回避のためVercelサーバレス関数で中継:

- `GET /api/open-bids?q=キーワード&count=60` → XMLをJSON化して返す
- 取得項目: 案件名 / 発注機関 / 公告日 / **入札期日(TenderSubmissionDeadline)** / 調達区分 / 入札方式 / 公告原文URL
- 予定価格は事前非公表が多く未取得。金額不明のため勝率は親和性×競争環境ベースで算定(現職なしの新規競争として entry=0.85)
- クライアント側で業種分類・DI親和性・推定勝率を付与し、そのまま②〜⑦の戦略分析へ流せる

> 勝率は競合・コンペを織り込むため控えめ(過去実績の挑戦者上限60%、公示中の最良ケースでも約48%)。

## 4観点スコアリングの考え方 (build.py)

- **業界業種**: 案件名・省庁からルールベースで12業種に分類(広報/Web/IT/調査/電気/建設…)。
- **DI親和性 (0-100)**: 業種ベース値 + 案件名キーワード(SEO/広告/Web/デジタルマーケ等)加点、
  インフラ・工事系は減点。DI(SEO/運用型広告/Web制作/DX/データ分析)の事業領域への合致度。
- **落札可能性 (%)**: `親和性/100 × 現職タイプ係数 × 金額障壁係数 ÷ 推定入札者数 × 2`(上限60%)。
  競合他社・コンペの存在(推定入札者2〜6.5社)を織り込み、平均的な応札者の勝率1/nを基準に算定。
- **DI競合度 (参入度 0-100)**: `現職タイプ係数 × 金額障壁係数 × 100`。
  現職タイプ係数=一般企業1.0/大手広告0.78/団体0.55/大手SI 0.30/キャリア0.15/建設0.05。
  金額障壁係数=統一資格の等級・実績要件のクリアしやすさ(〜1千万=1.0…10億超=0.15)。
  レベル(参入容易/競争可能/要準備/参入困難/対象外)ごとに取るべきアクションを画面に明記。
- **狙い目スコア (0-100)**: `落札可能性×0.5 + 案件規模の魅力×0.2 + DI親和性×0.3` の透明な加重平均。
  70+=最優先 / 50-69=積極検討 / 30-49=条件次第 / 30未満=見送り。表では3成分の色帯で内訳を可視化。

## 予測・学習機能 (TimesFM / TabFM の思想の軽量実装)

> 本家 [google-research/timesfm](https://github.com/google-research/timesfm) /
> [google-research/tabfm](https://github.com/google-research/tabfm) は数GBのチェックポイント+GPU前提のため、
> 本ダッシュボードでは両者のアプローチを純Pythonで軽量に再現している(依存ライブラリゼロ)。

- **TabFM流 = 類似案件からの文脈内学習**: 案件名の文字bigramベクトルでk近傍(k=8)の類似案件を検索し、
  `予測勝率 = ルールベース勝率×(1-α) + 類似案件の実績勝率(類似度加重平均)×α`(α=平均類似度、上限0.45)。
  過信気味のルールベース値を実データで補正する。
- **TimesFM流 = 年度再帰予測**: 官公庁調達の「令和N年度→N+1年度」再帰性を利用し、
  来年度に再公告されそうな案件(=今後の勝てそうなネタ)を予測。
  `勝てる期待値 = 再公告確率(継続キーワードで最大85%) × 予測勝率`。公告予測時期・予想金額つき。
- APIの時系列が単一日付に偏るため、月次時系列予測でなく年度サイクル予測を採用(データ制約への対応)。

いずれも **DI基準の推定・参考値**。実際の公告・入札可否・勝敗を保証するものではない。

## データ更新 / 再ビルド

```bash
export DW_API_KEY="＜Data-Walkers APIキー＞"
rm -f raw.json            # 最新データを取り直す場合
python build.py           # raw.json → data.json / data.js を再生成
```

- APIキーはコミットしない(環境変数 `DW_API_KEY` から読む)。
- `raw.json` があればAPIキー無しでも再集計のみ可能。
- API仕様上1回あたり最大1000件のため、本画面は代表サンプル1000件(全43,008件)を分析対象とする。
